# 情景对话作业 — 语音提交方案

## 1. 现状分析

### 1.1 已有的能力（可直接复用）

| 模块 | 现状 | 关键文件 |
|------|------|----------|
| 情景对话引擎 | 完整的语音对话链路：录音→ASR→LLM回复→TTS播报，支持 46 个内置场景 + 15 个角色扮演场景 | `ConversationController.java`, `ConversationServiceImpl.java`, `conversationStore.ts` |
| 作业系统 | 支持 PRONOUNCE / CONVERSATION / GRAMMAR 三种作业类型，教师可布置、查看提交报告、点评 | `AssignmentController.java`, `AssignmentServiceImpl.java` |
| 语音录制 | Push-to-Talk 录音 Hook，WebM 自动转 WAV(16kHz Mono PCM)，<0.5s 判无效 | `useRecorder.ts`, `audio.ts` |
| AI 评分 | 对话结束后独立 LLM 调用评分（语法/相关性/流利度），Temperature=0.1-0.3 | `ConversationServiceImpl.endSession()` |
| 数据存储 | `conversation_sessions` 存储会话记录+评分，`conversation_messages` 存储每轮消息+音频URL | V3/V30 迁移脚本 |

### 1.2 当前缺口

- **学生提交只有文本框**：`MyClassesPage.tsx` 的提交弹窗是 `<textarea>`，与作业类型无关
- **后端提交接口只收文本**：`submitAssignment(studentId, assignmentId, text)` 只有 `text` 参数
- **作业表缺少对话配置**：`assignment` 表没有存储"指定哪个场景"和"要求什么难度"的字段
- **教师创建作业时没有场景选择**：`AssignmentListPage.tsx` 创建作业时只有标题+类型+说明，CONVERSATION 类型选不了具体场景

### 1.3 已有的字段（尚未利用）

`assignment_submission` 表已有这些字段但从未写入：
- `audio_url` VARCHAR(500) — 录音 URL
- `practice_record_id` BIGINT — 关联练习记录
- `score` DECIMAL(5,2) — AI 评分

## 2. 方案设计

### 2.1 核心思路

**情景对话作业 = 老师指定场景 + 学生完成语音对话 + 对话记录自动成为提交**

学生不再是"打字提交"，而是：
1. 看到作业 → 点击"开始练习"
2. 进入对话页面（复用已有 ConversationPage 的 UI 和交互）
3. 完成语音对话 → AI 自动评分
4. 对话记录 + 评分自动关联到作业提交

### 2.2 数据模型变更

#### assignment 表增加字段（Flyway 迁移 V31）

```sql
ALTER TABLE assignment
  ADD COLUMN scene_key VARCHAR(50) COMMENT '内置场景标识(如restaurant/airport)，与content_id二选一',
  ADD COLUMN difficulty VARCHAR(20) DEFAULT 'MEDIUM' COMMENT '难度 EASY/MEDIUM/HARD',
  ADD COLUMN required_rounds INT DEFAULT 5 COMMENT '要求对话轮数，默认5轮';
```

说明：
- `content_id` 复用：指向 `roleplay_scenes.id`（角色扮演场景）；与 `scene_key` 二选一
- 教师创建 CONVERSATION 作业时，必选一个场景（内置 46 场景或角色扮演 15 场景）
- `difficulty` 和 `required_rounds` 带默认值，教师可覆盖

#### 无需新增表

`assignment_submission` 已有 `practice_record_id`、`audio_url`、`score` 字段，无需 DDL 变更。

### 2.3 后端 API 变更

#### 2.3.1 教师端：创建作业接口扩展

**文件**: `AssignmentCreateDTO.java` — 增加 3 个可选字段

```java
private String sceneKey;      // 内置场景 key
private String difficulty;    // EASY/MEDIUM/HARD
private Integer requiredRounds; // 要求轮数，默认 5
```

`AssignmentServiceImpl.createAssignment()` 将新字段写入 assignment 表。

#### 2.3.2 学生端：新增"以对话记录提交"接口

**文件**: `JoinClassController.java` — 新增端点

```
POST /api/v1/user/class/assignments/{assignmentId}/submit-conversation
Body: { "sessionId": 12345 }
```

**文件**: `AssignmentServiceImpl.java` — 新增方法 `submitConversationAssignment`

```java
@Transactional
public void submitConversationAssignment(Long studentId, Long assignmentId, Long sessionId) {
    // 1. 校验作业存在且已发布，类型为 CONVERSATION
    // 2. 校验学生在班级中
    // 3. 校验 conversation_session 存在且属于当前学生，状态为 completed
    // 4. 从 conversation_session 提取：
    //    - total_score → submission.score
    //    - session_id → submission.practiceRecordId
    //    - 从 conversation_messages 拼接对话文本 → submission.textContent
    // 5. 检查是否已有提交记录：
    //    - 有 → 更新（允许重交，覆盖旧记录）
    //    - 无 → 新增
    // 6. 递增 assignment.submit_count（仅首次）
}
```

#### 2.3.3 学生端：获取作业详情接口（供对话页使用）

**文件**: `JoinClassController.java` — 新增端点

```
GET /api/v1/user/class/assignments/{assignmentId}
```

返回作业完整信息（含 `sceneKey`、`contentId`、`difficulty`、`requiredRounds`），供前端对话页初始化场景。

#### 2.3.4 教师端：提交详情展示对话内容

`getSubmissionDetail` 和 `getAssignmentReport` 现有逻辑中，当 `practiceRecordId != null` 时，额外查询 `conversation_messages` 表返回对话逐轮记录。

### 2.4 前端变更

- 场景选择器（从 roleplay_scenes API 获取列表 + 内置 46 场景下拉）
- 难度选择（EASY / MEDIUM / HARD）
- 要求轮数（默认 5）

#### 2.4.2 学生作业列表 — 区分提交方式

**文件**: `MyClassesPage.tsx`

| 作业类型 | 按钮文案 | 点击行为 |
|---------|---------|---------|
| PRONOUNCE（跟读） | "提交作业" | 弹出文本框（现有逻辑不变） |
| **CONVERSATION（对话）** | **"开始练习"** | **跳转到对话练习页** |
| GRAMMAR（语法） | "提交作业" | 弹出文本框（现有逻辑不变） |

#### 2.4.3 新增：作业对话练习页

**新文件**: `AssignmentConversationPage.tsx`

这是核心新增页面。路由：`/student/assignment/:assignmentId/practice`

**页面结构**（最大化复用现有组件）：

```
┌─────────────────────────────────────┐
│  ← 返回    餐厅点餐 · 中等难度       │  ← 顶栏（显示场景名+难度）
│                        第 2/5 轮    │
├─────────────────────────────────────┤
│                                     │
│  🤖 AI: Welcome to our restaurant!  │  ← 消息气泡列表
│       What would you like to order? │    （复用 ConversationPage 的
│                                     │     消息渲染逻辑）
│  😊 你: I'd like a hamburger please │
│                                     │
│  🤖 AI: Great choice! Anything...  │
│                                     │
├─────────────────────────────────────┤
│  🔴 按住说话                        │  ← Push-to-Talk 按钮
│                                     │    （复用 useRecorder hook）
└─────────────────────────────────────┘
```

**关键流程**：

```
页面加载
  │
  ├─ 1. GET /user/class/assignments/{id}  → 获取作业配置（场景、难度、轮数）
  │
  ├─ 2. POST /chat/session/start          → 创建对话会话（传入 sceneKey/contentId）
  │      └─ conversationStore 接管消息状态
  │
  ├─ 3. 对话进行中（与 ConversationPage 完全相同）
  │      └─ 长按录音 → ASR → LLM 回复 → TTS 播报
  │
  ├─ 4. 点击"结束对话" 或 达到 requiredRounds
  │      └─ POST /chat/end/{sessionId}    → 获取 AI 评分
  │
  ├─ 5. ScoreModal 展示评分
  │      └─ 用户点击"提交作业"
  │
  └─ 6. POST /submit-conversation         → 提交对话记录为作业
         └─ 跳转回 MyClassesPage（显示"已提交"）
```

**与现有 ConversationPage 的差异**：
- 场景/难度不由用户选择，而是从作业配置读取（禁用场景选择器）
- 显示"第 X/N 轮"进度
- 对话结束后的 ScoreModal 增加"提交作业"按钮
- 提交成功后跳回作业列表而非留在对话页
- 增加"返回"按钮（放弃本次练习，回到作业列表）

**代码复用策略**：
- `conversationStore.ts` — 直接复用，不修改
- `useRecorder.ts` — 直接复用
- `ConversationPage.tsx` 的消息渲染逻辑 — 提取为共享组件或直接在 AssignmentConversationPage 中重写（该页面 ~250 行，可接受少量重复）

## 3. 完整交互流程

### 3.1 教师发布对话作业

```
教师进入作业管理 → 点击"发布作业"
  → 选择班级
  → 选择类型: "情景对话"
  → 填写标题（如"Unit 3 餐厅点餐练习"）
  → 选择场景（从角色扮演场景列表或内置场景下拉中选择）
  → 选择难度（默认 MEDIUM）
  → 设置要求轮数（默认 5）
  → 填写说明（可选）
  → 设置截止日期
  → 发布
```

### 3.2 学生完成对话作业

```
学生进入"我的班级" → 看到对话类作业卡片
  → 点击"开始练习"
  → 进入对话页 → 场景自动加载 → AI 发起首轮对话
  → 按住录音 → 说话 → 松手发送
  → AI 文字回复 + TTS 语音播报
  → 重复对话 N 轮
  → 点击"结束对话"（或达到要求轮数自动提示）
  → AI 评分展示：总分 + 语法/相关性/流利度 + 评语
  → 点击"提交作业"
  → 返回到作业列表 → 状态变为"已提交"
```

### 3.3 教师批改对话作业

```
教师进入作业详情 → 查看提交报告
  → 点击已提交学生的"展开" → 看到：
    - 对话逐轮记录（文字）
    - AI 评分（语法/相关性/流利度/总分）
  → 教师输入评分(1-100) + 文字评语
  → 提交点评 → 学生端可见
```

## 5. 边界条件与注意事项

### 5.1 重复提交
- 学生可以多次练习并重新提交（覆盖旧记录），以最后一次为准
- 首次提交才递增 `submit_count`，覆盖不递增

### 5.2 中断恢复
- 学生练习中途退出（关闭页面/断网），已有的 active session 会保留
- 下次进入时调用 `GET /chat/session/active` 恢复未完成的对话
- 但未结束的对话不能提交（`submit-conversation` 校验 session.status == 'completed'）

### 5.3 场景校验
- 教师布置的作业指定了场景 A，学生如果绕开作业页面直接去自由练习页完成场景 B 的对话，用那个 sessionId 来提交应被拒绝
- 后端校验：提交的 `session_id` 对应的 scene/sceneKey 必须与作业配置一致

### 5.4 截止日期
- 超过 `deadline` 后，`submit-conversation` 返回错误"作业已截止"
- 对话中达到截止时间：前端在对话页定时检查，截止前 5 分钟给出提示

### 5.5 安全性（遵循 CLAUDE.md 已有规则）
- 对话内容（ASR 文本）在存入 `text_content` 前做长度限制（≤2000 字符摘要）
- `correct_answer` 不适用于对话类型，无泄露风险
- 所有 LLM 调用走后端 AI Gateway，API Key 不暴露到前端

### 5.6 跟读类型（PRONOUNCE）暂不改造
- 跟读作业目前也是文本框提交，但跟读的语音练习已有独立流程（发音评测页面）
- 跟读类型改造作为后续迭代，本次方案只处理 CONVERSATION 类型

## 6. 备选方案对比

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| **A（推荐）** | 新增独立作业对话页，复用 conversationStore | 复用度高，不影响现有自由练习功能 | 需要新增 1 个页面 |
| B | 改造现有 ConversationPage，增加"作业模式"参数 | 代码量最少 | 自由练习和作业逻辑耦合，后续维护困难 |
| C | 在 MyClassesPage 内嵌 iframe 或弹窗对话 | 学生不用跳转页面 | 移动端体验差，iframe 通信复杂 |

**推荐方案 A**：页面级复用（Zustand store + hooks），UI 组件适度重复（~200 行可接受），自由练习与作业提交逻辑解耦。
